# 본문을 더 편하게 읽기 — 각주와 글자 크기, 마크다운 강조 개선

> 이 글은 이전 브랜드와 구현을 다룬 작업 기록입니다. 현재 브랜드는 **Biwoom - 비움**, 공개 주소는 https://biwoom.github.io/ 입니다.

보리도의 TEXT와 STORY는 문헌과 이야기를 길게 읽는 공간이다. 이번에는 본문에서 각주를 확인하고 읽던 자리로 돌아가는 동작, 글자 크기를 조절하는 도구, 한국어 문장의 강조 표현을 중심으로 읽기 환경을 다듬었다. 랜딩페이지의 소개 영역도 메뉴 색상을 활용하도록 바꿨다.

## 각주를 확인하고 읽던 자리로 돌아오기

개별 문서의 본문 우상단 도구모음에 각주 아이콘을 추가했다. PC에서는 아이콘 옆에 ‘각주’를 함께 표시한다. 아이콘을 누르면 기존 목차와 같은 형태의 패널이 화면 오른쪽에서 열린다.

각주 내용은 원본 Markdown을 빌드할 때 해석해 패널에 배치한다. 브라우저에서 원본을 다시 불러오지 않으며, 각주 안의 강조와 링크도 유지한다. 각주가 없는 문서에서는 버튼을 비활성화한다.

본문의 각주 번호를 누르면 패널이 열리고 해당 항목이 선택된다. 반대로 패널 안의 각주 텍스트를 누르면 패널이 닫히면서 본문 번호로 돌아간다. 별도의 ‘↩’ 링크는 제거했고, 키보드로 각주 항목에 접근해 Enter로 이동할 수도 있다. 각주 안에 작성한 일반 링크는 원래 동작을 유지한다.

같은 각주가 본문에 여러 번 등장하면 마지막으로 누른 번호로 돌아간다. 도구모음에서 바로 패널을 연 경우에는 첫 번째 참조가 기본 복귀 위치다. 선택한 본문 번호는 배경색과 굵기를 바꿔 쉽게 찾을 수 있게 했다. 패널 안에서도 각주 번호와 내용이 같은 행에서 시작하고, 긴 설명은 내용 영역 안에서 줄바꿈되도록 정렬했다.

## 슬라이더 하나로 제목과 본문 크기 조절

폰트 아이콘 아래에는 글자 크기 패널을 추가했다. 슬라이더 하나로 읽기 영역의 제목·소제목·본문을 기존 크기의 80~150% 범위에서 함께 조절한다. 각 요소의 크기 비율은 유지하며, 슬라이더를 움직이는 즉시 반영한다.

현재 배율을 표시하고, 슬라이더 아래에 ‘초기화’ 버튼을 뒀다. 선택값은 브라우저에 저장해 다른 TEXT·STORY 문서에서도 이어서 사용한다. 저장 기능을 사용할 수 없는 환경에서도 현재 페이지의 크기 조절은 가능하다.

모바일에서는 패널을 화면 가로 중앙에 맞추되, 세로로는 폰트 아이콘 바로 아래에 배치했다. 스크롤하거나 화면 크기를 바꿔도 아이콘 위치를 따라간다. 사이트 메뉴와 상단 문서 소개 영역은 글자 크기 조절 대상에서 제외했다.

## 목차와 각주 패널의 움직임 정리

목차와 각주 패널이 빠르게 튀어나오는 느낌도 수정했다. 기존에는 180ms의 짧은 CSS 이동과 다음 프레임의 클래스 변경을 사용했다. 화면 밖에 놓인 패널을 대화상자로 여는 과정에서 자동 포커스와 스크롤이 겹칠 여지도 있었다.

두 패널이 공통 제어 코드를 사용하도록 정리하고, 열림은 360ms, 닫힘은 280ms로 조정했다. 고정 타이머로 대화상자를 닫는 대신 실제 애니메이션이 끝난 뒤 닫는다. 열리는 도중 닫아도 현재 위치에서 이어서 움직인다.

각주 선택 시에는 패널 내부 목록만 스크롤하도록 했으며, 스크롤 잠금에 따른 본문 좌우 이동도 줄였다. 닫기 버튼·Esc·배경 클릭과 포커스 복귀를 유지하고, 동작 줄이기 설정에서는 이동 애니메이션을 생략한다.

## 문장부호와 한국어 조사 사이의 강조

다음처럼 괄호나 따옴표를 포함한 강조 뒤에 조사가 바로 붙으면, 기본 Markdown 해석 규칙에서는 별표가 강조 기호로 인식되지 않는 경우가 있었다.

```md
*아마라와띠(Amaravatī)*라는 도시가 있었다.
그 이름은 **“불사의 도시, 신들의 도시”**라는 뜻이다.
**이제(二諦義)**에는 열 가지 중첩된 뜻이 있다.
```

원문에 불필요한 공백이나 HTML을 추가하는 대신, 공통 파서에 [remark-cjk-friendly](https://github.com/tats-u/markdown-cjk-friendly) 확장을 적용했다. 화면을 만드는 과정과 제목·요약·링크를 분석하는 과정이 같은 플러그인 구성을 사용하도록 묶었다. 본문뿐 아니라 제목·표·링크·각주 안에서도 같은 강조 규칙을 적용한다.

코드 블록과 인라인 코드, 역슬래시로 이스케이프한 별표는 그대로 남는다. 짝이 맞지 않는 기호나 강조 안쪽의 불필요한 공백까지 자동으로 고치는 기능은 아니다. Obsidian 등 다른 앱의 미리보기는 각 앱의 해석에 따라 사이트와 다를 수 있다.

이탤릭에는 별도의 표시 문제도 있었다. `<em>`이 만들어져도 전역의 `font-synthesis: none` 설정이 브라우저의 기울임 합성을 막고 있었다. 현재 불러오는 Pretendard에는 별도 이탤릭 글꼴이 없어, 본문 강조 요소에만 `font-synthesis: style`을 허용하도록 했다. Markdown 해석과 실제 글꼴 표시는 서로 다른 단계에서 확인해야 했다.

## 라이선스 문구와 랜딩 배경

개별 문서 하단에 자동으로 붙던 기본 ‘비움 · CC0’ 문구는 표시하지 않도록 했다. 저장된 권리 메타데이터는 유지하며, 외부 자료처럼 별도로 지정한 권리자·라이선스·고지문은 계속 표시한다.

랜딩페이지의 소개 영역인 `ol-manifest`는 접속하거나 새로고침할 때 메뉴 색상 중 하나를 무작위로 선택한다. HOME의 청록색, TEXT의 금색, STORY의 연두색과 BLOG의 기존 흑백 표현을 활용한다. 밝은 배경에서는 글자를 어둡게 표시하며, 뒤로가기로 페이지가 복원될 때도 다시 선택한다. 배경의 장식 문구는 BORIDO로 맞췄다.

## 확인한 범위와 남은 점검

콘텐츠·회귀 테스트 42개, 타입 검사, 정적 빌드, 생성된 페이지의 링크와 UI 구조 검사를 수행했다. 각주 복귀 대상, 글자 크기 저장·초기화, 한국어 강조, 기본 라이선스 문구의 생략과 개별 권리 예외를 확인했다. 랜딩 배경은 네 가지 선택지와 페이지 복원 동작을 따로 점검했다.

실제 STORY 빌드와 로컬 개발 서버 응답에서 예시 문장이 이탤릭·볼드 태그로 변환되는 것도 확인했다. 브라우저에서의 시각적 배치와 직접 조작 검증은 도구 접근 제한으로 완료하지 못했으므로, 다양한 화면 크기에서의 최종 사용성 점검은 남아 있다.

이번 기록과 변경 사항은 로컬 Git 커밋으로 묶는다. 원격 업로드와 운영 사이트 배포는 이번 작업에 포함하지 않는다.
