# OL core 내부 안정화 점검

- 버전: 1.0
- 최종 갱신: 2026-11-13
- 대상: Biwoom - 비움, `ol-core/`
- 운영 주소: https://biwoom.github.io/
- 원칙: 기능·디자인·본문·공개 주소를 보존하고, 확인된 중복과 불일치만 수정한다.

## 점검 및 수정

| 영역 | 확인한 문제 | 적용 내용 |
| --- | --- | --- |
| 콘텐츠 로더 | ID 생성과 정규화가 문서마다 레지스트리를 다시 읽음. 스키마 파일에 파일 입출력·감시 구현이 섞임 | `src/lib/content-loaders.ts`로 로딩을 분리. 갱신마다 준비한 레지스트리를 ID 생성과 정규화에 공유. 새 갱신은 항상 다시 준비하며, glob 실행 중 새 파일이 들어오면 재준비한다. |
| Markdown 해석 | 매 호출마다 파서 설정을 구성하고, 같은 제목·설명 추출에 AST를 여러 번 생성 | 파서 설정만 한 번 고정하고 AST는 호출마다 새로 생성. 문서/폴더의 제목과 설명을 함께 추출하여 최대 한 번 해석한다. 전역 AST·메타데이터 캐시는 사용하지 않는다. |
| 개발 서버 감시 | 컬렉션과 자산 감시가 별도 구현. 자산 갱신 콜백은 이전 비동기 작업과 겹칠 수 있음 | 공통 `watchContent`를 사용해 비동기 갱신을 순차 처리. 기존 대기 시간 250/200ms 유지. 자산 감시는 레지스트리 쓰기에 반응하지 않고, 종료 시 리스너·타이머·대기 작업을 해제한다. |
| CSS | 옛 목차 패널 선택자와 두 파일의 동일한 다크 모드 선언이 남아 있음 | 사용처가 없는 목차 선택자 분기 32개와 앞쪽의 중복 다크 규칙 6개 제거. 뒤쪽의 유효 선언과 적용 순서를 유지하고 인접한 동일 선택자만 합친다. |
| TEXT 렌더링 | 출력에 쓰지 않는 서지 필드를 만들기 위해 본문 전체를 해석 | TextReader의 미사용 호출·import 제거. 다른 용도로 쓰일 수 있는 서지 해석 함수는 유지한다. |
| 생성 링크 검사 | 정상 한글 각주 ID를 무조건 디코딩하여 누락으로 오판. 잘못된 퍼센트 인코딩은 검사 자체를 중단할 수 있음 | 리더와 같이 원형 ID를 먼저 찾고 디코딩을 대체 수단으로 사용. 실제 누락은 계속 오류로 보고한다. 검사 함수를 CLI와 분리하고, 한 번의 검사 안에서 대상 HTML 읽기를 재사용한다. |

## 검토 후 유지한 부분

- 작성자 입력 검증과 Astro 정규화 스키마는 서로 다른 경계를 담당한다. 스키마의 필드·허용 값·기본 동작·태그 변환은 변경하지 않았다. 스키마는 `src/content.config.ts`, 원고 해석은 `scripts/lib/content.mjs`에 유지한다.
- TEXT/STORY의 도구·각주·모달·원문·패널 크기 조절은 이미 공유된다. 두 workspace의 좌우 패널 기본 상태와 도킹 정책에는 차이가 있으므로 코드 형태가 비슷하다는 이유만으로 합치지 않았다. 클라이언트 스크립트는 변경하지 않았다.
- CSS의 서로 다른 반응형·다크 모드·학술 리더 재정의는 단순 중복으로 취급하지 않았다. 이번 삭제는 사용처 부재 또는 뒤쪽의 완전히 같은 선언으로 입증되는 부분에 한정한다.
- 폴더 메타정보의 전역 캐시와 추가 의존성 변경은 도입하지 않았다. 편집 중 비공개 전환·이동·삭제 결과가 오래 남는 위험을 피하면서, 한 번의 작업 범위에서만 데이터를 재사용한다.

## 검증 결과

- 수정 전 전체 소스와 콘텐츠를 임시 복사본에 보관하고, 같은 원고로 수정 전후 `build:site`를 실행했다. 콘텐츠 제외·링크 수정 없이 두 정적 생성과 Pagefind 색인을 완료했다. 이는 아래 표준 `build`의 실패를 해소한 결과가 아니다.
- 등록 Markdown 문서 368개, 폴더 메타정보 68개의 정규화 결과가 동일하다. 전체 대상 Markdown AST, 공개 경로와 활성 리디렉션도 동일하다.
- HTML 424개는 CSS 자산 파일명의 해시를 제외하면 동일하다. 클라이언트 JavaScript 번들은 바이트 단위로 동일하다. 활성 CSS 선택자의 선언을 미디어/레이어/키프레임 문맥별로 비교하여 일치를 확인했다. CSS 총량은 286,453 → 283,450바이트로 3,003바이트 감소했다.
- RSS, sitemap-index, sitemap-0, robots는 바이트 단위로 동일하다. 비교에 사용한 원고·첨부의 바이트와 `content-registry.json`도 변경 전과 동일하다.
- 회귀 검사 106개 중 105개 통과. 추가한 파서 격리, 감시 순차 처리·실패 복구·종료·필터, 실제 렌더링된 한글 각주 링크 검사를 모두 통과했다. 유일한 실패는 실제 원고 검사기를 호출하는 기존 경로 검사이며, 아래 22건이 원인이다.
- `typecheck`: 오류·경고·힌트 0개. `check:registry`: 기준 시점에 통과. 검증 말미에 별도로 들어온 STORY `01-예경과-저술의-뜻.md`의 선두 빈 줄 추가와 이에 따른 레지스트리 해시 변경은 보존했다. 이 후속 편집은 동일 원고 비교 대상과 구분하며, 현재 미커밋 레지스트리까지 HEAD와 같다고 주장하지 않는다.
- `check:live`: 임시 개발 서버에 HTTP로 접근해 TEXT/STORY 문서·PDF 갱신, 원문 도구, BLOG 권리, NFC/NFD 경로, 공개/비공개 전환, MEDIA 추가·이동·삭제, EBOOK 비공개 자산 제거·복원을 확인했다. 브라우저 자동화가 아니다.
- 생성 HTML/CSS 계약: 독자 문서 334개, BLOG와 EBOOK 통과. 운영 도메인 검사: 메타정보/피드/사이트맵 URL 1,579개 및 robots 통과.
- `check`, 표준 `build`, 생성 링크 검사를 포함하는 `check:built`는 기존 TEXT 원고의 glossary/prepared/raw/context 누락 링크 22건 때문에 통과하지 못한다. 수정 전후 원고 오류 목록은 동일하다. 한글 각주의 잘못된 누락 판정은 제거됐으며 실제 누락 링크는 그대로 검출한다.
- 브라우저를 열거나 화면·애니메이션을 시각 검증하지 않았다. 원본 작업 공간의 dist를 임시 산출물로 교체하지 않았고, 커밋·푸시·배포도 수행하지 않았다.

## 운영 시 주의

- 표준 전체 빌드를 통과하려면 누락된 원자료를 복원하거나 작성 의도에 맞게 해당 22개 원고 링크를 별도로 정리해야 한다. 이번 내부 코드 정리에서는 원고 내용을 변경하지 않았다.
- 콘텐츠 엔진 변경을 실행 중인 개발 서버에 확실히 반영하려면 개발 프로세스를 다시 시작한다. 이번 갱신 검사는 수정 코드를 새로 읽은 임시 서버에서 수행했다.

## 수정 변경사항

- 내부 코드 점검, 보존 비교, 적용한 안정화와 기존 콘텐츠 검증 제한을 기록했다.
