# Biwoom 콘텐츠 관리 매뉴얼

- 문서 버전: v4.7
- 최신 수정일: 2026-11-13
- 대상 프로젝트: Biwoom (OL 코어)
- 배포 URL: https://biwoom.github.io/

## 콘텐츠와 OL 코어의 위치

- `content/`: Obsidian 보관함과 원본 문서·첨부파일. 기존 보관함의 `.obsidian`은 내용 수정 없이 함께 이동했다. Obsidian에서 새 content/ 위치를 열어 사용한다.
- `ol-core/src/`, `ol-core/scripts/`, `ol-core/public/`: Astro 구현·콘텐츠 엔진·고정 자산. 콘텐츠와 구분하여 관리한다.
- 저장소 루트의 `astro.config.mjs`, package 파일, `site-config.mjs`, `content-registry.json`과 `dist/` 출력은 유지한다. npm 명령도 루트에서 실행한다.
- 파일시스템 경로는 `ol-core/scripts/lib/paths.mjs`의 공통 기준을 사용한다. glob()은 실제 content 경로를 읽고, registry 내부 키는 기존 `text/...` 같은 보관함 상대 경로를 유지한다. 보관함의 저장 위치만 바꾸었다고 문서 URL·발행일을 새로 만들지 않는다.
- 한글 경로는 내부 색인·로더·상대 링크·생성 첨부 주소에서 NFC로 통일한다. macOS에서 NFD로 읽히는 파일명도 공통 contentFile 경로 조회로 지원한다. 파일명을 직접 변환하거나 본문을 다시 저장할 필요는 없다. 과거 레지스트리의 경로 키·seriesKey·categoryKey·별칭은 준비 과정에서 NFC로 이관하되 ID·URL·발행일·해시·리디렉션은 보존한다. 같은 NFC 경로로 겹치는 파일이나 충돌하는 레지스트리는 검사 오류이며 자동 덮어쓰지 않는다.
- 생성 자산은 `ol-core/public/generated/`, 개발 메타데이터는 `.astro/`에 있으며 커밋하지 않는다. `.gitignore`는 `content/.obsidian/`을 제외한다.

## 집필 원칙

`content/`를 Obsidian 보관함으로 사용한다. 제목과 본문을 작성하고 폴더를 관리하면 Astro가 소속·순서·요약·목차·읽기 시간을 계산한다. Vault CMS·Front Matter·Decap CMS는 사용하지 않는다.

```text
text/001.중관부/001.대승현론/01.번역/001.1권.md
text/001.중관부/001.대승현론/02.연구/001.독립 연구.md
story/001.불전문학/010.시리즈/010.파트/001.이야기.md
blog/005.비움제작일지/006.일지/기록.md
media/001.인포그래픽/lamrim-preview1.jpg
```

- TEXT는 카테고리 → 문헌 → 자료 구분 → 개별 자료, STORY는 카테고리 → 시리즈 → 파트 → 문서 구조다. 연구와 번역의 권별 대응은 없다.
- TEXT의 상위 폴더는 `001.중관부`, `002.반야부`, `003.정토부`, `004.선어록`, `005.아비달마부`, `006.유가부`, `007.화엄부`, `008.인명부`, `009.대승부`, `010.니까야`다. 각 폴더에는 제목·소개를 담은 소문자 `index.md`를 둔다. 기존 중관부의 대승현론은 그대로 유지하며, 나머지 9개 카테고리는 소개만 준비한 상태다. 새 문헌과 본문은 사용자가 향후 추가한다.
- `/text/`는 문헌 목록, `/story/`는 작품 카드다. 기본 화면 하단의 최근 공개 글은 개별 읽기 화면으로 이어진다. 카테고리 탭은 각각 `/text/categories/`, `/story/categories/`로 연결되며, 카테고리 카드를 선택하면 해당 문헌·작품 목록으로 이동한다. 빈 공개 카테고리도 표시한다. Git에 빈 폴더를 보관하려면 `.gitkeep`을 둔다.
- TEXT·STORY 카테고리의 소문자 `index.md`는 소개·메타정보다. 선택적 title → 첫 H1 → 번호 없는 폴더명 순서로 제목을 정하고, description이 없으면 첫 설명 문단을 요약으로 사용한다. 소개는 카테고리 카드와 상세 화면에 표시하며, 본문 자료·시리즈·통계에 포함하지 않는다. 소개의 정규 주소는 카테고리 주소이며 `published: false`는 하위 문서와 전용 첨부까지 숨긴다.
- STORY의 주제는 ‘이야기불교’이며 상위 폴더는 `001.붓다전기`, `002.전생이야기`, `003.고승전기`, `004.가르침과 일화`, `005.설화와 전승`, `006.구법과 순례`, `007.시와 게송`이다. 기존 마하붓다왐사 두 판본은 붓다전기에 둔다. 다른 여섯 카테고리는 소개만 준비했으며 작품·본문은 사용자가 향후 추가한다. 담마빠다이야기는 가르침과 일화, 정토왕생집은 설화와 전승에 배치할 계획이다. 선시는 향후 시와 게송 아래 작품으로 추가한다.
- 숫자 접두어는 정렬에 사용하며 화면에서 숨긴다. 서로 다른 자릿수도 허용한다.
- 제목은 선택적 `title`, 첫 H1, 번호 제거 파일명 순으로 결정한다. 번호만 있는 파일에는 H1을 쓴다.
- YAML은 필요하지 않다. 개별 예외가 있을 때만 아래 필드를 사용한다.
- H1은 사이트 제목으로 표시하고 본문에서 한 번 제거한다. 사이트는 목차를 자동 생성하며 본문의 별도 `목차` 절은 사이트 렌더링에서 내부 앵커 링크 목록으로 확인된 경우에만 생략한다. 다른 본문은 보존한다. 원본은 보존한다.
- 본문 출전·주석을 권장한다. 엔터티·관계 객체를 작성하지 않는다.

## BLOG 시리즈·카테고리·포스트

BLOG는 `blog/시리즈/카테고리/포스트` 구조다. 카테고리는 한 시리즈에만 속하며, 같은 표시명의 카테고리를 여러 시리즈에 중복 배치하지 않는다. 번호는 순서에만 사용한다.

- `001.불교의 세계/001.교학/`
- `002.수행-몸과 마음 돌보기/002.수행/`
- `003.에세이-삶의 쉼표/`: 소개만 준비했다. 사용자 집필 전에는 카테고리·샘플 포스트를 만들지 않는다.
- `004.상상공장/003.인포그래픽/`, `004.상상공장/004.디자인/`
- `005.비움제작일지/005.비움/`, `005.비움제작일지/006.일지/`

포스트는 카테고리 바로 아래 Markdown 또는 `글이름/index.md`와 첨부 폴더로 작성한다. 시리즈와 카테고리의 `index.md`는 소개·메타정보이며 포스트 수, 최신 글, RSS에 포함하지 않는다. 파일이 없어도 폴더명으로 목록을 만들며 빈 폴더는 `.gitkeep`으로 보관한다. 루트의 독립 글은 미분류로 유지한다.

두 단계 index.md 모두 선택적 title → 첫 H1 → 번호 없는 폴더명 순서로 제목을 정한다. description이 없으면 첫 설명 문단을 요약으로 사용한다. 본문은 Markdown 소개로 표시한다. 선택적 `thumbnailAsset: ./cover.jpg`로 표지를 지정할 수 있으며, 시리즈는 표지가 없어도 기본 도형 표지를 사용한다. `published: false`이면 해당 시리즈·카테고리와 모든 하위 글·전용 첨부를 숨긴다. 기존 개별 글의 비공개·날짜·권리 예외는 유지한다. 태그는 개별 글에만 적용하고 소개에서 상속하지 않는다.

`/blog/`는 최신 포스트 목록, `/blog/series/`는 시리즈 목록이다. 포스트/시리즈는 별도 페이지 링크다. 네 시리즈의 표지 순서와 비대칭 크기는 방문 시 한 번 무작위로 배치하며 비움제작일지는 아래 고정 영역에 표시한다. 모바일 표지는 읽기 편한 1열이다. 고정 제작일지 대상 폴더는 site-config.mjs의 BLOG.journalSeries에서 관리한다. 시리즈·카테고리 상세 주소는 레지스트리로 보존한다.

시리즈의 읽기 순서는 기본적으로 발행일 오래된 순이다. 별도 순서가 필요하면 해당 시리즈 index.md에 다음 형식을 쓴다.

```md
# 시리즈 제목

시리즈 소개입니다.

## 읽는 순서

1. [먼저 읽을 글](001.카테고리/첫글.md)
2. [다음 글](002.다른카테고리/글폴더/index.md)
```

같은 시리즈 안의 실제 포스트만 연결한다. 중복·다른 시리즈·없는 글은 검사에서 오류로 알린다. 명시하지 않은 공개 글은 뒤에 날짜순으로 붙고, 공개 목차·처음부터 읽기·이전/다음은 모두 이 순서를 사용한다. 읽는 순서 절은 소개 본문에 중복 표시하지 않는다. 나머지 Markdown은 그대로 표시한다.

포스트 목록은 카테고리·정확한 태그·연도의 교집합으로 추린다. `?category=교학&tag=중도` 링크를 유지하고, 필터를 바꾸면 더 보기 범위를 초기화한다. 카테고리 선택 시 해당 index.md 소개가 표시되며 카테고리 전체 페이지로 이동할 수 있다. 시리즈 상세에서는 카테고리를 걸러 목차를 잘라내지 않고 전체 읽기 흐름을 유지한다.

폴더 이동 시 문서와 첨부를 함께 옮기고 상대 링크를 갱신한다. 원문 수정 전에 레지스트리 이동을 연결하여 기존 ID·주소·발행일을 보존하고 준비된 레지스트리도 함께 보관한다. 2026-11-11 이동 목록은 `.agents/references/blog-series-migration.json`에 있다.

## 강조 문법과 한국어 조사

사이트는 `remark-cjk-friendly/parseOnly`를 공통 Markdown 파서에 적용한다. 문장부호와 한국어 조사가 강조 경계에 붙어도 원문을 바꾸지 않고 해석한다.

```md
*아마라와띠(Amaravatī)*라는 도시가 있었다.
그 이름은 **“불사의 도시, 신들의 도시”**라는 뜻이다.
**용어(설명)**를 강조한다.
```

본문·제목·목록·표·링크·각주에서 같은 규칙을 사용한다. 코드 블록·인라인 코드와 역슬래시로 이스케이프한 별표는 그대로 표시한다. 별표 안쪽의 불필요한 공백이나 짝이 맞지 않는 기호까지 보정하지는 않는다. Obsidian 등 다른 앱의 미리보기는 해당 앱의 Markdown 해석에 따라 사이트와 다를 수 있다.

렌더링과 제목·요약·첨부 분석은 `ol-core/scripts/lib/markdown.mjs`의 동일한 플러그인 목록을 사용한다. 이 파서 모듈을 바꾼 뒤에는 개발 서버를 완전히 재시작한다.

## 선택적 frontmatter

허용 필드는 `title`, `description`, `tags`, `date`, `published`, `license`, `licenseUrl`, `rightsHolder`, `copyrightNotice`, `lang`, `thumbnailAsset`이다. 자료의 라이선스·권리·출전은 자동 추정하지 않는다.

`series`, `part`, `category`, `chapter`, `order`, `entities`, `relations`, `tagAliases`, `status`, `version` 등 과거 필드는 사용하지 않는다. 날짜는 자동 색인 또는 기존 값, 공개 여부는 예약 경로와 선택적 `published`로 결정한다. 태그는 선택적 단순 문자열 배열이다. `tags: [수메다, 수밋따, 아라와띠]`처럼 작성하고, `인물/수메다` 같은 분류 접두어와 단수 `tag:`는 사용하지 않는다. `prefixTags`는 사용하지 않는다.

기본 작성자·언어·라이선스는 `site-config.mjs`에 있고, 개별 권리 예외를 우선한다. 앱에서는 `ol-core/src/lib/site-config.ts`를 사용한다.

## 소개·공개

- 문헌·시리즈 소개는 해당 폴더의 `index.md`에 선택적으로 작성한다. 소개가 없어도 문헌과 목록이 생성된다.
- `_drafts`, `_templates`, 숨김 폴더는 공개 입력에서 제외한다. 이곳에 초안을 작성하고 완성하면 메뉴의 공개 위치로 옮긴다.
- 공개 폴더의 문서는 기본 공개 대상이다. 로컬 작성과 실제 GitHub 업로드·배포는 별개다.
- `published: false`는 비공개다. 시리즈 소개의 비공개 값은 하위 자료에도 적용한다.
- TEXT는 학술형 문헌 안내·자료 목록·서지 영역과 전용 읽기 화면을 사용한다. 자료 구분 버튼은 첫 자료로 이동하고 목록을 펼쳐 탐색하며, 실제 탭 전환은 아니다. 번역과 연구의 이전·다음 이동은 같은 자료 구분 안에서만 이어진다.
- 태그는 개별 문서에 직접 입력된 경우만 제목 아래에 이름만 표시한다. 태그가 없으면 영역을 생성하지 않으며, 시리즈 태그를 하위 문서로 상속하지 않는다. 시리즈 태그 메뉴·모달은 제거했다.
- BLOG도 같은 단순 태그를 사용한다. 태그별 버튼은 사이드바 아카이브 아래의 기본 닫힘 ‘태그’ 패널에 표시하며, 기존 카테고리·연도 필터와 함께 적용하며, 필터를 바꾸면 더 보기 표시를 첫 묶음으로 초기화한다. 전체에는 태그 없는 글도 포함한다. 글 상단의 태그 링크는 BLOG의 해당 태그 분류로 연결된다.

## TEXT 학술형 읽기 화면

TEXT/STORY 본문과 각주에서 `*빨리어 로마자*`처럼 이탤릭으로 표시한 텍스트의 라틴 문자·결합 부호에는 Gentium 7.000의 실제 이탤릭 글꼴을 사용한다. `ā ī ū ṅ ñ ṭ ḍ ṇ ḷ ṃ`과 결합형 장음·점 부호를 같은 글꼴로 표시하도록 구성했다. 이탤릭 영역의 영어 등 다른 라틴 문자에도 같은 글꼴을 적용한다. 한국어 본문은 기존 명조, 각주는 기존 UI 글꼴을 유지하고 일반 본문·원문 코드 블록·일반 코드의 글꼴과 글자 크기 조절 방식은 유지한다. 빨리어 자체의 철자나 유니코드 표기는 자동으로 변경하지 않는다. 글꼴은 사이트에 포함한 원본 WOFF2 자산이며 OFL 라이선스를 함께 보관한다. 브라우저 화면 확인은 사용자가 직접 수행하며 별도 명시 요청 전에는 에이전트가 브라우저를 열지 않는다.

문헌 목차와 문서 화면은 청회색, 명조 본문과 산세리프 도구·목록을 사용한다. 금색은 TEXT 메뉴·카테고리와 문서의 각주 강조에 사용한다. TEXT 개별 문서는 1360px 이상에서 문헌 목록과 본문 목차를 기본으로 열고, 그 미만에서는 기본 닫힘으로 시작한다. 넓은 PC에서 양쪽을 열면 문서 목록·본문·목차/각주 보조 영역의 3단, 작은 화면에서는 2단 또는 본문과 대화상자로 전환한다. 목차·각주 데이터는 복제하지 않는다. TEXT/STORY 개별 문서 본문은 Noto Serif KR 17px, 줄간격 1.95와 최대 780px 가운데 정렬을 공유한다. 본문 제목·문단 간격도 같으며 메뉴·도구·강조색은 각 메뉴의 스타일을 유지한다. 글자 크기 슬라이더는 이 기본값을 기준으로 동작한다. 저장한 80–150% 비율은 문서가 처음 표시되기 전에 적용하므로 다음 문서로 이동할 때 기본 크기에서 저장 크기로 바뀌는 깜박임을 방지한다. TEXT 개별 문서는 스크롤 시 사이트 메뉴·문헌 안내·파트 버튼이 위로 사라지고 도구모음과 열린 보조 패널이 화면 최상단에 고정된다. 문헌 목차 페이지와 STORY의 헤더 동작은 유지한다.

기존 각주 텍스트 클릭 복귀, 단일 글자 크기 슬라이더·초기화·브라우저 저장, 복사 기능을 유지한다. TEXT 도구모음은 샘플 기호와 PC 집중/기본 전환을 제공한다. 모바일에서는 집중 버튼을 숨기고 문헌 목차 버튼을 ‘문헌’으로, TEXT의 본문 목차 버튼은 ‘목차’로 줄여 표시한다. 데스크톱의 ‘본문 목차’ 표기는 유지한다. 집중 모드에서는 좌우 패널을 숨기고, 집중 모드를 끝내면 이전 좌우 패널 상태를 복원한다. 선택문 인용 복사는 본문 선택문·문서 제목·공개 URL을, 현재 절 링크 복사는 현재 제목 앵커를 사용한다. 인쇄 시 각주는 본문 아래로 배치한다.

TEXT/STORY는 1360px 이상에서 본문과 오른쪽 보조 패널의 경계선을 드래그해 ‘본문 목차 / 각주’ 패널 너비를 조절할 수 있다. 기본 300px, 최소 240px, 최대 520px이며 본문 영역은 최소 480px를 확보하도록 화면에 맞춰 제한한다. 본문은 남은 공간에 따라 조정하되 최대 읽기 너비 780px를 유지한다. 경계선은 Tab으로 접근하고 왼쪽 방향키로 넓히기, 오른쪽 방향키로 좁히기, Home/End로 최소/최대, Enter 또는 더블클릭으로 기본 너비 복원이 가능하다. 선택한 너비는 두 메뉴에서 함께 기억하며 다음 문서의 첫 표시 전에 적용한다. 화면 축소로 임시 제한되거나 집중 모드·목차/각주 전환을 거쳐도 선호 너비를 유지한다. 1360px 미만의 모달과 인쇄에는 조절 손잡이를 표시하지 않는다. 왼쪽 문헌 목차 너비는 기존대로 유지한다.

TEXT 문헌 폴더의 `index.md` 본문은 library 우측 ‘서지정보’에 Markdown 그대로 표시한다. 원문열람 URL·링크·강조·목록을 지원하며 중앙에 중복 출력하지 않는다. 본문이 없으면 이 영역을 생략한다. 간단한 소개는 기존 `description`에 적고, 새 메타데이터 필드는 요구하지 않는다. 개별 문서 화면의 서지 정보는 자료 본문에 명시된 `저자:`, `원저자:`, `저본:`, `출처:`, `원제:`, `번역자:`, `연구자:` 표기만 읽는다. 새 YAML 필드는 요구하지 않으며, 코드 블록에서 메타데이터를 추정하지 않는다. library에는 자료별 서지 표기를 중복 나열하지 않는다. 원문 링크는 `[CBETA 원문 열람 ↗](https://cbetaonline.dila.edu.tw/zh-tw/T1853)`처럼 표시 문구를 지정할 수 있다. 원문 인용 스타일은 작성자가 명시한 Markdown 인용문에 적용하며 한자 문단을 자동 분류하지 않는다.

## TEXT·STORY 원문 표시

번역문에 함께 싣는 원문은 시작 삼중 백틱 뒤에 `original`을 붙인다. 한자 문장을 자동으로 원문으로 분류하지 않는다.

````markdown
한국어 번역문입니다.

```original
二諦義有十重。
```
````

TEXT·STORY 개별 문서에서 이 블록이 있으면 문헌 목차 옆에 ‘원문 숨기기 / 원문 보기’ 버튼이 표시된다. 기본은 원문 표시이며, 모바일(980px 이하)은 상태에 따른 눈 아이콘만 표시한다. 버튼의 접근성 설명은 유지한다. 일반 코드 블록과 인라인 코드는 전환 대상이 아니다.

원문 배경은 TEXT에서는 좌우 패널과 같은 테마별 옅은 색상, STORY에서는 해당 테마의 보조 배경색을 사용한다. 원문은 18px 명조 계열, 1.95 줄간격과 자동 줄바꿈으로 표시하며 기존 글자 크기 슬라이더로 함께 확대·축소한다. 본문의 번역과 원문 텍스트는 그대로 보존된다.

## EBOOK 전자책 라이브러리

`/ebook/`는 완성된 EPUB·PDF를 내려받는 보조 라이브러리다. 상단·모바일 메인메뉴에 추가하지 않고 푸터 PROJECTS의 MEDIA 바로 아래에서 연결한다. 개별 상세페이지 없이 카드 선택 시 서지정보·다운로드 모달을 연다. 전자책 전체의 이용조건은 CC0 1.0으로 통일한다.

```text
ebook/001.카테고리/001.문헌명/
├── index.md        # 선택: 서지정보와 소개
├── cover.jpg       # 선택: cover 또는 표지 이름 권장
├── 문헌명.epub
└── 문헌명.pdf
```

ebook 바로 아래의 최상위 폴더가 카테고리이며, 각 카테고리 안에 한 권당 하위 폴더 하나를 만든다. 카테고리와 책의 숫자 접두어는 정렬에만 사용하고 화면 이름에서는 숨긴다. 빈 공개 카테고리도 버튼으로 표시하며 Git에 남기려면 `.gitkeep`을 둔다. 샘플 카테고리와 기존 테스트 전자책은 `ebook/001.샘플/001.보리도 전자책 샘플/`에 유지한다. 제목은 선택적 title → 첫 H1 → 폴더명 순서다. EPUB·PDF 중 하나 이상이 있어야 등록되며, 비어 있는 파일은 제외한다. 표지는 cover/표지의 PNG·JPG·JPEG·WebP·AVIF를 우선하고, 없으면 첫 이미지, 이미지가 없으면 기본 타이포 표지를 쓴다. 파일이 여러 개면 다운로드 버튼도 각각 표시한다.

index.md는 YAML 없이 쓸 수 있다. 일반 문단에 `저자:`, `원저자:`, `번역자:`, `편집자:`, `발행일:`, `판본:`, `언어:`를 줄별로 작성하고, 책 소개를 이어 쓴다. 작성하지 않은 서지항목은 추측하지 않는다. `원문: [온라인에서 읽기](../../../text/.../index.md)`처럼 공개 TEXT·STORY 원문을 상대 Markdown 링크로 연결할 수 있다. 코드 블록의 서지정보는 해석하지 않는다.

책 폴더의 index.md에 `published: false`를 명시하면 표지와 다운로드까지 배포에서 제외한다. 카테고리 index.md의 비공개 설정은 해당 카테고리와 소속 책 전체에, ebook/index.md의 비공개 설정은 전체 전자책에 적용한다. `_drafts`·점폴더·밑줄폴더와 내부 assets는 등록하지 않는다. 배포 파일은 선택된 표지와 공개 EPUB·PDF만이며 `/generated/content/ebook/`는 빌드 산출물이다. 원본 EPUB·PDF 제작이나 기존 TEXT·STORY 원문의 수정은 자동으로 하지 않는다.

목록 상단에 전체 및 카테고리별 권수 버튼을 표시한다. 카테고리 선택과 검색, 전체/EPUB/PDF 형식 필터는 함께 적용한다. `?book=식별자`는 모달 공유 주소이며 카테고리 또는 책 폴더 경로를 변경하면 식별자와 파일 주소도 달라진다. EBOOK은 개별 문서 레지스트리·RSS 항목을 만들지 않는다. 추가·교체 후에는 빌드와 check:built를 실행해 실제 배포 파일을 확인한다.

STORY 개별 문서는 1360px 이상에서 오른쪽 ‘본문 목차 / 각주’ 고정 패널을 항상 표시한다. 기본 선택은 본문 목차이며, 목차가 없으면 각주를 표시한다. 둘 다 없으면 안내 문구를 표시한다. 패널 배경은 본문과 같고, 집중 모드는 좌우 패널을 모두 숨기고, 해제하면 이전에 선택한 보조 패널을 복원한다. 1360px 미만에서는 동일한 목차·각주 노드를 기존 모달로 사용하며, 화면을 줄였다고 모달을 자동으로 열지 않는다.

## 자료와 링크

- 공용 이미지는 `content/media/`에 둔다. 첫 하위 폴더를 분류로 사용한다. 예: `media/001.인포그래픽/도표.png` → 인포그래픽. 숫자 접두어는 정렬에만 사용하고, 더 깊은 폴더도 첫 분류에 포함한다. 현재 공개 이미지 12개는 `001.인포그래픽` 5개(불교 세계관·람림·여섯 단계), `002.문양` 5개(인드라망 문양·픽토그래프), `003.일러스트` 2개(수메다·수밋타)로 나눈다. 새 이미지도 내용에 맞는 최상위 카테고리 안에 넣는다. 루트 이미지는 미분류다. 이미지마다 frontmatter나 문서 색인을 작성하지 않는다. 폴더 이동 시 기존 상대 링크를 갱신하고, 문서 해시가 바뀌면 준비된 content-registry.json도 함께 보관한다.
- `/media/`는 보조 이미지 모음이다. 상단·모바일 메뉴에는 숨기고 홈 미디어 통계와 푸터에서 연결한다. 카테고리 버튼으로 masonry 목록을 분류하고 같은 페이지의 모달에서 화면 맞춤·원본 크기 전환을 제공한다. Esc·닫기·바깥 클릭으로 닫고 원래 이미지 버튼으로 포커스를 돌려준다.
- 문서 기준 상대 Markdown 링크를 사용한다. 예: `blog/005.비움제작일지/006.일지/기록.md`에서 `![설명](../../../media/001.인포그래픽/lamrim-preview1.jpg)`. 폴더 깊이에 맞는 상대 경로를 쓰며, 위키링크나 임의의 브라우저 `/media/...` 주소로 대체하지 않는다.
- 기존 이미지를 분류 폴더로 옮기거나 이름을 바꾸면 문서의 상대 링크도 함께 갱신한다. 현재 이미지 12개는 최상위 카테고리 폴더에 있다. 썸네일 원본 `*-thumb.jpg` 3개는 삭제했으며 복원하지 않는다. 갤러리용 자동 미리보기는 유지한다. 최초 분류 당시 15개의 경로·체크섬 기록은 `.agents/references/media-category-migration.json`에 보관한다.
- 홈 통계는 모음에 표시되는 원본 이미지 파일 수만 센다. 미리보기·숨김·초안·Markdown은 집계하지 않는다.
- `npm run sync:assets`는 원본과 가벼운 WebP 미리보기를 준비한다. 미리보기는 `ol-core/public/generated/media-gallery/`, 캐시는 `.astro/media-gallery-cache.json`에 생성되며 커밋하지 않는다.
- 공용 자산은 `ol-core/public/generated/content/media/`로 동기화한다. 이 폴더는 공유 공개 자산이므로 참조 문서의 비공개 여부를 상속하지 않는다. 숨김·초안 파일과 Markdown은 배포하지 않는다. 문서 전용 비공개 첨부는 아래 기존 전용 폴더 규칙을 따른다.

- 목록에 표시할 PDF·이미지·HTML은 자료 구분 폴더에 직접 둔다. 파일명이 제목이 된다.
- 본문 보조 자료는 `assets/` 또는 `_assets/`에 두고 상대 Markdown 링크를 쓴다. 해당 폴더는 개별 자료 목록에서 제외한다.
- 문서 간 상대 `.md` 링크는 공개 URL로 변환한다. URL 앵커는 실제 제목에 맞춰 작성한다.
- 위키링크, 블록 참조, Obsidian 전용 임베드는 현재 지원하지 않는다.
- 이관 자료의 `content-asset:컬렉션/경로`는 일반 생성 자산으로 해석한다. 새 글은 상대 링크를 우선한다.
- `design-asset:`와 `/generated/design/`를 새로 작성하지 않는다. DESIGN 전용 resolver와 환경변수는 폐지했다.
- 생성 결과는 `ol-core/public/generated/content/`다. 직접 수정하거나 커밋하지 않는다.
- `.obsidian/`과 개인 작업창·플러그인은 커밋하지 않는다.

## 첨부 공개 범위와 경로 제한

- TEXT는 정확히 카테고리/문헌/자료구분/자료, STORY는 카테고리/시리즈/파트/자료 깊이로 작성한다. 문헌·시리즈 루트 index.md만 소개로 사용한다.
- `_`로 시작하는 경로는 제외하며 `_assets`만 보조 첨부용 예외다.
- `published: false`인 index.md가 있는 폴더의 첨부는 배포하지 않는다. 같은 디렉터리의 여러 문서를 독립 관리하려면 각 글 전용 폴더/index.md/assets 구조를 쓰거나 초안 첨부를 _drafts 안에 둔다.
- 느슨한 문서에서만 참조되는 첨부는 그 문서가 비공개이면 배포하지 않는다. 공개 문서도 참조하는 공유 첨부는 공개다. 아무 글도 참조하지 않는 공개 위치의 첨부는 공개 공유 자료로 취급한다.
- 삭제한 콘텐츠는 복원하거나 무관한 페이지로 안내하지 않는다. 과거 registry 기록은 보존하되 목적지가 사라진 redirect는 생성하지 않는다. 남은 글의 끊어진 링크는 글자를 보존하며 제거한다.

## 주소와 최초 공개 준비일

`content-registry.json`을 콘텐츠와 함께 보관한다. 문서 식별자·URL·날짜, 폴더 주소, 해시와 이전 경로를 자동 기록한다. `npm run prepare:content`, 검사·개발·빌드에서 갱신한다. 파일 수정 시각이나 매 빌드 시각으로 발행일을 덮어쓰지 않는다.

내용을 그대로 유지한 이동·이름 변경은 해시로 연결한다. 개발 서버가 꺼진 동안 이동과 내용을 동시에 변경했거나 동일 내용의 문서가 여러 개라 모호하면, 준비 명령 전에 명시적으로 연결한다.

```sh
npm run content:move -- "text/이전경로.md" "text/새경로.md"
```

본문이 바뀐 이동을 어떤 경우든 자동 인식한다고 가정하지 않는다. 최초 공개 준비일은 Asia/Seoul 날짜이며 실제 배포 완료일과 다르다. 문헌 소개의 주소는 문헌 주소와 같다. 기존 공개 URL은 색인에 유지하며, 폐지 자료의 구주소는 필요한 경우 새 일반 자료로 이동 안내한다. 이동 안내 페이지는 검색·사이트맵에서 제외한다.

연속 이동은 과거 별칭도 최종 경로로 연결한다. 명령 실행 전 이전 파일이 없어야 하며 복사에는 사용하지 않는다. 컬렉션 간 이동은 명령으로 처리하지 않는다. 대상 컬렉션 URL을 명시적으로 배정하고 기존 URL→새 URL redirect 및 별칭을 함께 검증한다.

초안에서 공개 폴더로 이동한 뒤 prepare:content와 검증을 실행하고 원본과 registry를 함께 커밋한다. registry가 없으면 Git에서 복원한다. 새 프로젝트에서만 `npm run prepare:content -- --init`을 사용한다. 기존 운영 registry를 초기화하지 않는다.

## 개발 서버 갱신

일반 Markdown·폴더 변경은 개발 서버가 자동 반영한다. 단, `ol-core/scripts/lib/content.mjs`, `ol-core/scripts/prepare-content.mjs` 등 경로 해석·색인 엔진 코드를 수정했을 때는 실행 중인 `npm run dev`를 Ctrl+C로 완전히 종료한 뒤 다시 실행한다. 페이지 새로고침이나 설정 파일 touch만으로 Node에 남아 있는 이전 모듈이 교체된다고 가정하지 않는다. 오래된 서버가 registry를 다시 쓸 수 있으므로 재시작 후 `npm run prepare:content`와 실제 목록 확인을 수행한다.

## MEDIA 이미지 정보 작성

카테고리 폴더의 선택적 `index.md` 하나에서 여러 이미지의 정보를 관리한다. 참고 예시는 `content/media/001.인포그래픽/index.md`, `002.문양/index.md`, `003.일러스트/index.md`에 유지한다. YAML은 필요하지 않다.

```markdown
# 일러스트

이곳에는 작성 안내를 적을 수 있다. 첫 이미지 항목 전의 내용은 모달에 표시하지 않는다.

## [수메다와 수밋타의 첫 만남](sumedha-sumitta.png)

이미지 설명을 여러 문단으로 작성한다.

- 제작자: 확인된 이름
- 이용조건: 확인된 이용조건

### 출처

[관련 글](../../blog/카테고리/문서/index.md)

## [수밋타 인물화](sumitta-profile.jpg)

두 번째 이미지의 설명을 작성한다.
```

- 정확히 `## [제목](파일경로)` 형식의 H2가 이미지 항목을 시작한다. 경로는 index.md 기준이며 같은 카테고리 안의 실제 공개 이미지여야 한다. 하위 폴더는 `하위폴더/이미지.png`로 쓴다. 다른 카테고리·외부 이미지·초안·없는 파일과 중복 등록은 검사에서 오류로 알린다.
- 제목은 카드와 모달에 표시한다. 설명은 다음 H1 또는 H2 전까지이며, H3 이하 소제목·문단·목록·강조·일반 Markdown 링크를 사용할 수 있다. 코드 블록 안의 작성 예시는 항목으로 해석하지 않는다. 설명 링크도 기존 공통 Markdown 규칙으로 공개 주소에 연결한다.
- MEDIA 이미지의 기본 라이선스는 CC0다. 다른 라이선스가 적용되는 이미지에는 해당 항목의 본문에 이용조건을 별도로 표기한다. 페이지 소개 아래에도 기본 CC0·예외 별도 표기 안내를 표시한다.
- 제작자·날짜·이용조건은 확인된 정보만 본문에 쓴다. 누락된 정보를 자동으로 추정하지 않는다. 항목이 없는 이미지는 파일명을 쓰고 설명 영역을 숨긴다.
- 데스크톱 모달에서는 이미지 오른쪽에 설명을, 900px 이하에서는 이미지 아래에 설명을 표시한다. 긴 설명은 자체 스크롤을 사용하며 기존 화면 맞춤·원본 크기·닫기 동작을 유지한다.
- index.md는 공개 문서·검색·RSS·레지스트리 항목이나 배포용 Markdown 파일로 만들지 않는다. 이미지 개수에도 포함하지 않는다. index.md의 `published: false`는 설명만 숨기며, 기존 공유 이미지의 공개 상태는 바꾸지 않는다. 비공개 이미지는 `_drafts` 등 기존 제외 경로에 둔다.
- index.md를 수정·삭제하면 다음 갱신/빌드에 제목·설명이 반영되며, 변경 없는 이미지의 미리보기는 재사용한다.

## 검증·배포

```sh
npm run check
npm run typecheck
npm run build
npm run check:built
```

YAML 없는 글, 제목, 경로 계층, 중복 주소, 링크와 자산, 초안 제외를 검사한다. 실제 TEXT 문헌·자료와 PDF가 `dist/`에 생성되었는지 확인한다. 변경되는 메뉴와 기존 공개 URL도 확인한다.

GitHub Pages 루트 배포를 유지하며 Astro `base`는 설정하지 않는다. 라우트 변경 시 robots·RSS·사이트맵을 함께 검사한다. 업로드 요청은 요청된 push까지만 수행하며 배포 확인·후속 로그 커밋을 자동으로 하지 않는다.
