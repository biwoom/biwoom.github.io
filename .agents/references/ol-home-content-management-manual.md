# BORIDO 콘텐츠 관리 매뉴얼

- 문서 버전: v2.1
- 최신 수정일: 2026-10-30
- 대상 프로젝트: BORIDO (OL 코어)
- 배포 URL: https://biwoom.github.io/

## 집필 원칙

`src/content/`를 Obsidian 보관함으로 사용한다. 제목과 본문을 작성하고 폴더를 관리하면 Astro가 소속·순서·요약·목차·읽기 시간을 계산한다. Vault CMS·Front Matter·Decap CMS는 사용하지 않는다.

```text
text/001.중관부/001.대승현론/01.번역/001.1권.md
text/001.중관부/001.대승현론/02.연구/001.독립 연구.md
story/010.시리즈/010.파트/001.이야기.md
blog/기록.md
```

- TEXT는 카테고리 → 문헌 → 자료 구분 → 개별 자료 구조다. 연구와 번역의 권별 대응은 없다.
- 숫자 접두어는 정렬에 사용하며 화면에서 숨긴다. 서로 다른 자릿수도 허용한다.
- 제목은 선택적 `title`, 첫 H1, 번호 제거 파일명 순으로 결정한다. 번호만 있는 파일에는 H1을 쓴다.
- YAML은 필요하지 않다. 개별 예외가 있을 때만 아래 필드를 사용한다.
- H1은 사이트 제목으로 표시하고 본문에서 한 번 제거한다. 사이트는 목차를 자동 생성하며 본문의 별도 `목차` 절은 사이트 렌더링에서 내부 앵커 링크 목록으로 확인된 경우에만 생략한다. 다른 본문은 보존한다. 원본은 보존한다.
- 본문 출전·주석을 권장한다. 엔터티·관계 객체를 작성하지 않는다.

## 선택적 frontmatter

허용 필드는 `title`, `description`, `tags`, `date`, `published`, `license`, `licenseUrl`, `rightsHolder`, `copyrightNotice`, `lang`, `thumbnailAsset`이다. 자료의 라이선스·권리·출전은 자동 추정하지 않는다.

`series`, `part`, `category`, `chapter`, `order`, `entities`, `relations`, `tagAliases`, `status`, `version` 등 과거 필드는 사용하지 않는다. 날짜는 자동 색인 또는 기존 값, 공개 여부는 예약 경로와 선택적 `published`로 결정한다. 태그는 문자열 배열이며 접두어는 선택 사항이다. `prefixTags`는 사용하지 않는다.

기본 작성자·언어·라이선스는 `site-config.mjs`에 있고, 개별 권리 예외를 우선한다. 앱에서는 `src/lib/site-config.ts`를 사용한다.

## 소개·공개

- 문헌·시리즈 소개는 해당 폴더의 `index.md`에 선택적으로 작성한다. 소개가 없어도 문헌과 목록이 생성된다.
- `_drafts`, `_templates`, 숨김 폴더는 공개 입력에서 제외한다. 이곳에 초안을 작성하고 완성하면 메뉴의 공개 위치로 옮긴다.
- 공개 폴더의 문서는 기본 공개 대상이다. 로컬 작성과 실제 GitHub 업로드·배포는 별개다.
- `published: false`는 비공개다. 시리즈 소개의 비공개 값은 하위 자료에도 적용한다.
- TEXT 문헌 화면은 현재 STORY의 자료 구분 링크와 펼침 목록을 공유한다. 버튼은 첫 자료로 이동하며 실제 탭 전환이 아니다.
- 태그가 있을 때만 공통 태그 모달을 표시한다. 태그 없이 작성·발행할 수 있다.

## 자료와 링크

- 목록에 표시할 PDF·이미지·HTML은 자료 구분 폴더에 직접 둔다. 파일명이 제목이 된다.
- 본문 보조 자료는 `assets/` 또는 `_assets/`에 두고 상대 Markdown 링크를 쓴다. 해당 폴더는 개별 자료 목록에서 제외한다.
- 문서 간 상대 `.md` 링크는 공개 URL로 변환한다. URL 앵커는 실제 제목에 맞춰 작성한다.
- 위키링크, 블록 참조, Obsidian 전용 임베드는 현재 지원하지 않는다.
- 이관 자료의 `content-asset:컬렉션/경로`는 일반 생성 자산으로 해석한다. 새 글은 상대 링크를 우선한다.
- `design-asset:`와 `/generated/design/`를 새로 작성하지 않는다. DESIGN 전용 resolver와 환경변수는 폐지했다.
- 생성 결과는 `public/generated/content/`다. 직접 수정하거나 커밋하지 않는다.
- `.obsidian/`과 개인 작업창·플러그인은 커밋하지 않는다.

## 첨부 공개 범위와 경로 제한

- TEXT는 정확히 카테고리/문헌/자료구분/자료, STORY는 시리즈/파트/자료 깊이로 작성한다. 문헌·시리즈 루트 index.md만 소개로 사용한다.
- `_`로 시작하는 경로는 제외하며 `_assets`만 보조 첨부용 예외다.
- `published: false`인 index.md가 있는 폴더의 첨부는 배포하지 않는다. 같은 디렉터리의 여러 문서를 독립 관리하려면 각 글 전용 폴더/index.md/assets 구조를 쓰거나 초안 첨부를 _drafts 안에 둔다.
- 느슨한 문서에서만 참조되는 첨부는 그 문서가 비공개이면 배포하지 않는다. 공개 문서도 참조하는 공유 첨부는 공개다. 아무 글도 참조하지 않는 공개 위치의 첨부는 공개 공유 자료로 취급한다.
- 삭제한 콘텐츠는 복원하거나 무관한 페이지로 안내하지 않는다. 과거 registry 기록은 보존하되 목적지가 사라진 redirect는 생성하지 않는다. 남은 글의 끊어진 링크는 글자를 보존하며 제거한다.

## 주소와 최초 공개 준비일

`content-registry.json`을 콘텐츠와 함께 보관한다. 문서 식별자·URL·날짜, 폴더 주소, 해시와 이전 경로를 자동 기록한다. `npm run prepare:content`, 검사·개발·빌드에서 갱신한다. 파일 수정 시각이나 매 빌드 시각으로 발행일을 덮어쓰지 않는다.

내용을 그대로 유지한 이동·이름 변경은 해시로 연결한다. 개발 서버가 꺼진 동안 이동과 내용을 동시에 변경했거나 동일 내용의 문서가 여러 개라 모호하면, 준비 명령 전에 명시적으로 연결한다.

```sh
npm run content:move -- "text/이전경로.md" "text/새경로.md"
```

본문이 바뀐 이동을 어떤 경우든 자동 인식한다고 가정하지 않는다. 최초 공개 준비일은 Asia/Seoul 날짜이며 실제 배포 완료일과 다르다. 문헌 소개의 주소는 문헌 주소와 같다. 기존 공개 URL은 색인에 유지하며, 폐지 자료의 구주소는 필요한 경우 새 일반 자료로 이동 안내한다. 이동 안내 페이지는 검색·사이트맵에서 제외한다.

연속 이동은 과거 별칭도 최종 경로로 연결한다. 명령 실행 전 이전 파일이 없어야 하며 복사에는 사용하지 않는다. 컬렉션 간 이동은 명령으로 처리하지 않는다. 대상 컬렉션 URL을 명시적으로 배정하고 기존 URL→새 URL redirect 및 별칭을 함께 검증한다.

초안에서 공개 폴더로 이동한 뒤 prepare:content와 검증을 실행하고 원본과 registry를 함께 커밋한다. registry가 없으면 Git에서 복원한다. 새 프로젝트에서만 `npm run prepare:content -- --init`을 사용한다. 기존 운영 registry를 초기화하지 않는다.

## 검증·배포

```sh
npm run check
npm run typecheck
npm run build
npm run check:built
```

YAML 없는 글, 제목, 경로 계층, 중복 주소, 링크와 자산, 초안 제외를 검사한다. 실제 TEXT 문헌·자료와 PDF가 `dist/`에 생성되었는지 확인한다. 변경되는 메뉴와 기존 공개 URL도 확인한다.

GitHub Pages 루트 배포를 유지하며 Astro `base`는 설정하지 않는다. 라우트 변경 시 robots·RSS·사이트맵을 함께 검사한다. 업로드 요청은 요청된 push까지만 수행하며 배포 확인·후속 로그 커밋을 자동으로 하지 않는다.
