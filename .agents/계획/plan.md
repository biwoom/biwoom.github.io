# 향후 작업 계획

- [x] 개별 페이지 본문 우상단 문서도구모음에 '각주아이콘' 추가, 원본 마크다운 문서의 각주를 빌드시 각주패널에 표시하도록 구현. 본문에서 각주아이콘 클릭시 각주패널이 열리도록 구현. 각주패널은 목차버튼과 같은 방식으로 구현.
- [x] 개별 페이지 본문 우상단 문서도구모음에 '폰트아이콘' 추가. 이 아이콘 클릭시 아이콘 하단에 본문제목과 본문폰트 사이즈를 조정할 수 있는 슬라이더패널이 열림. 슬라이더로 조정시 본문제목과 본문폰트 사이즈가 실시간으로 조정되도록 구현.
- [x] 미디어 페이지 구현. 미디어페이지는 홈 메뉴에는 숨김. 홈 랜딩 페이지 .ol-stat 섹션에 미디어 섹션추가하여 미디어자산 개수 표시. 미디어페이지 링크로 이동할 수 있게 함. 또 푸터영역에 미디어 링크를 추가하여 미디어페이지로 이동할 수 있도록 함. 미디어 폴더 하위 첫번재 폴더명을 카테고리로 활용. 이 카테고리 이요하여 미디어페이지에서 이미지 리스트 출력할 때 카테고리버튼을 표시. 이미지 리스트 형식은 masonry 형식으로 구현. 이미지 클릭시 모달로 이미지 확대보기 가능하도록 구현. 상세페이지 이동하지 않고 해당 미디어 페이지에서 모달로 구현.
- [x] 개별 문서 하단에 자동추가되는 '비움 · CC0' 라이선스 문구 삭제.
- [x] 개별 문서 마크다운 '**' 문자열이 본문에 그대로 출력되는 문제 수정.
- [x] 개별 문서 목차 버튼 클릭시 목차패널이 너무 빠르게 튕기듯 열리는 문제.
- [x] 랜딩페이지 ol-manifest 배경 컬러를 각 메뉴의 포인트 컬러로 랜덤하게 변경되도록 구현. 랜딩페이지 접속시 랜덤하게 변경되도록 구현.
- [x] TEXT 개별문헌 목차페이지와 개별문서 페이지에 대한 전체적인 UI/UX 개선. STORY와 차별화된 전문적이고 학술적인 느낌을 주도록 개선. STORY는 이야기와 스토리텔링 중심의 UI/UX라면 TEXT는 학술적이고 전문적인 느낌을 주도록 UI/UX 개선. 기존 개발했던 문서도구모음, 3단 레이아웃, 상단 파트 구분 버튼 등 주요 다지인 요소는 유지. 

- ASTRO glob() 로더 기능활용하여 프로젝트 루트로 content 폴더 이동하고 ASTRO 프로젝트 소스크드는 ol-core 폴더 내부로 이동.

- 공개사이트의 브랜드 주소를 borido.org 로 변경. 깃헙페이지에도 개인도메인을 연결한다.

- 블로그 내부 이미지들 미디어 자산으로 이동하고 포스트 내부 이미지 경로도 수정. 포스트 작성시 이미지는 미디어에 업로드하고 미디어 경로를 포스트에 삽입하도록 수정.

- 블로그 포스트 .ol-chips ol-blog-tag-chips 를 블로그 첫페이지 상단이 아니라 ol-blog-sidebar 내부 아카이브 하단에 배치. 태그 패널을 통해 포스트에 기록된 모든 태그를 확인하고 태그별로 포스트를 필터링할 수 있도록 구현. 태그 패널은 기본 닫힘 상태로 구현.

- 상위 카테고리 폴더와 문서폴더에 index.md 파일을 통해 카테고리와 문서의 메타정보 정의. index.md 파일에 정의된 메타정보를 통해 카테고리와 문서의 제목, 설명, 작성자, 태그, 문서서지정보 등을 정의하고 ASTRO 빌드시 해당 정보를 활용하여 카테고리와 문서의 메타정보를 자동으로 생성하도록 구현. 작성일, 수정일은 자동등록. index.md 파일 없을 경우 기본값으로 처리.

- 1.STORY 전체적인 스타일은 유지하되 개별문서 페이지 문서도구모음 아이콘을 TEXT페이지 문서도구모음 아이콘으로 교체. 2.스크롤시 STORY 개별문서페이지 최상단 메인메뉴 헤더 숨겨지게 적용. 3.STORY 모바일 페이지에도 TEXT 페이지처럼 최상단 메인메뉴 숨기고 상단에 문서도구모음 고정되게 적용.

- email: 'biwoom.ol@gmail.com' 수정. 경로 site.ts / borido.org@gmail.com 으로 이메일 주소 교체. 개별 문서페이지에 '수정 건의하기' 버튼 추가. 이 버튼 클릭시 모달패널이 열리고 모달패널 내부에 '수정 건의하기' 폼이 출력되도록 구현. 폼에는 수정 건의 내용 입력란, 건의자 별명, 건의자 이메일 입력란, 현재 문서 이름, 수정할 부분 입력공란, 제출 버튼이 포함되도록 구현. 제출 버튼 클릭시 입력된 내용과 이메일을 서버로 전송하고 서버에서 이메일로 전달되도록 구현. 제출 완료시 모달패널 닫히고 '수정 건의가 제출되었습니다.' 메시지 출력. EmailJS, 구글 앱스 스크립트 (Google Apps Script) 또는 다른 이메일 전송 API를 활용하여 구현. 최적의 방법 우선 조사하여 추천해줘. 깃헙페이지 정적사이트에 최적인 방법으로 안내해줘.
